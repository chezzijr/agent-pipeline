**`holistic-review` runs on a bounced diff, not on a class.**

The `review -> ok` row routed to `holistic-review` for every non-bugfix class.
Its own comment gave the real reason -- "a one-line bugfix's incremental review
already saw the whole diff" -- which is a property of the **diff**, not of the
class. A ticket of any class whose review returned `ok` on its first pass has
that same property.

The stage exists to catch incoherence *across* an accumulated diff: a fix in
loop 2 half-undoing loop 1's, error handling drifting between them. With
`review_loops == 0` nothing accumulated, so there is nothing to find. The
measurements say so: 6 runs, 6 `ok`, 0 findings, against a `review` that
returned `fail` 4 times in 20. The incremental pass earns its cost; the
holistic one did not.

A ticket that bounced still takes the holistic pass. That is its case, and the
new `review_loops: 1` variant in `test_stages.py` is what keeps its prompt file
enforced.

`transition()` is in `machine.FENCED`, so `CLAUDE.md` requires a human to see
this diff before it merges. It was written and reviewed by hand with the
dispatcher stopped, which *is* that review -- not a bypass of it.
